## 任务与执行归属

同轮七项：每小时宝箱、每日任务、视频任务、游戏任务、签到、章节卡兑换、免费抽奖；阅读积分额外可选，包括日读、周读800/1200分钟、作品更新提醒、阅读PK。

APP前台或后台实际能执行时本机优先，无需先上传。只有手动点击“一键同步并领取福利”、确认说明后才上传并启用云端兜底。首次启动、刷新、自动任务及连接失效不上传/更新登录凭据；已上传账号本机不能继续执行时，约90～120秒后云端接管，之后保留整点调度。系统冻结设置保持系统默认，不承诺后台常驻。

两端按账号互斥；APP在线让路或账号忙时，运维启动补跑正常跳过，不使Web退出、不排队重跑。登录确认失效后清空活动凭据并退出调度，保留微信绑定及身份，重新手动上传可恢复。普通网络/风控错误不按登录失效删除。

已完成、冷却、未达标、没有免费次数或非周日兑换均正常跳过，不等于漏跑。周日按实际余额降档：30碎片换一张20点卡，20～29换15点，15～19换10点，不足15跳过；每次兑换后回读，不充值或购买。

Web0.1.15为每小时广告增加独立冷却调度：官方`IntervalTime`按毫秒解释，保留2秒余量、每5秒检查本地期限，到期后再请求官方，仅补这一项，不重复整轮七项；正常空闲/网络条件下通常到期后数秒检查，不再跳过冷却尾巴后空等下一整点。仍遵守本机优先、互斥、暂停/失效与任务开关。重启先回读剩余冷却，不重置一小时或重复领取。

云端成功需同时核对具体`RewardList`、官方收益增加及同一任务冷却恢复，单有HTTP200/冷却变化不报到账；最多提交一次，延迟核验仅重读。日志记录具体奖励及前后数值，不把订阅券等累计收益当成点币余额。此项日志增强在Web核心生效，未声称未更新的APP本机引擎也具备新行为。Go/JS检查、Linux原生定时器回归及真实单项官方回执/收益核对已通过；未把尚未等待的自然完整一小时周期说成已观察完成。

APP逐事件保存七项和积分日志；固定执行ID补传不重做任务。常规日志30天，待传记录保留供导出，30天内自动补传；Web每账号保留最近3轮明细，独立幂等回执90天。旧版丢失记录不能补造。

## 部署与使用

1. 阅读[许可边界](LICENSE-SCOPE.md)、[免责声明](DISCLAIMER.md)、[隐私说明](PRIVACY.md)。
2. 按[云端部署教程](docs/DEPLOYMENT.md)部署自己服务器、配置HTTPS及可选微信功能。
3. 从[原项目](https://github.com/Xposed-Modules-Repo/cn.xihan.qdds)自行安装QDReadHook，在兼容的框架中启用原模块和本桥接，仅作用于自己的起点读书。
4. 设置 → QD模块设置 → 云端托管，选择任务。来源、作者与许可可在本页及独立桥接APP主页查看。
5. 需要云端才手动确认上传；不使用公共未知托管，不在Issue上传Cookie、配置或未脱敏日志。

运维、升级和回滚见部署教程；账号安全问题按[SECURITY.md](SECURITY.md)处理。提交改进前请读[CONTRIBUTING.md](CONTRIBUTING.md)。
